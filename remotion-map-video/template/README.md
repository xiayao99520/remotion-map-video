# 地图路线视频模板

把景点写进 JSON，即可预览和输出 MP4。主要适用于同一城市内的景点，也保留跨区域大圆航线。坐标始终是 `[经度, 纬度]`，底图使用 WGS84；不要直接填高德、百度地图的偏移坐标。

## 第一次使用

需要 Node.js 22.18 以上、npm、可访问 OpenFreeMap 的网络和中文字体。Windows 默认使用微软雅黑。安装一次依赖后即可复用：

```powershell
npm ci
npm run dev
```

默认示例为成都：宽窄巷子 → 小通巷 → 人民公园 → 春熙路 → 太古里 → 大慈寺。小通巷采用 OpenStreetMap 道路中心坐标，和宽窄巷子直线约 466 米，专门展示短路段自动放大。

## 粘贴中文路线

不用写 JSON 时，先把语料保存为 UTF-8 文本：

```text
城市：南宁
舒记粉店七星总店（七星路44号）车→三街两巷走路→亭子码头
```

```powershell
npm run route -- --input ../examples/nanning-food-resolved.txt --out ../examples/nanning-food.json --aspect 9:16
npm run route -- --text "雷峰塔车→柳浪闻莺走路→岳王庙" --city 杭州 --out out/hangzhou.json
npx remotion render MapRoute out/nanning-food.mp4 --props=../examples/nanning-food.json --gl=angle --concurrency=4
```

`→`、`->`、`=>` 都能用，全角/半角括号均可。交通方式写在箭头前，表示从这一站到下一站；没写默认走路并提示，末站后面的交通方式忽略。命令行 `--city` 优先于文本首行；没有城市就报错。多行内容请用 `--input`，避免 Windows 的 npm 命令转发丢失换行。

查询先确认城市范围，再依次查地名、地址、街道；手动坐标优先。命令输出固定四列表格 `去哪儿 | 下面的字 | 图标 | 怎么去`，并写出同名 `.geocode.json`（匹配方式、服务名称、来源链接、城市范围）。**街道近似只代表整条街，不代表准确店址**；地级市范围还可能包含下辖县，因此看到同名路必须核对行政区。表格下只有发现问题时才会出现需要确认的站。收到确认后再渲染。

没找到时退出码为 1，不写入或覆盖路线 JSON。两种补救：填写更具体的名字或附近地标；或在地址后写 `@纬度,经度`，例如 `冰神糖水铺（中山路256-1号）@22.8153525,108.3182634 高铁→`。内部自动换为 `[经度,纬度]`，也会检查是否在城市范围内。坐标请从谷歌地图或 OpenStreetMap 复制；高德、百度坐标有偏移。

南宁示例保留原文 `nanning-food.txt` 和人工补正后的 `nanning-food-resolved.txt`。舒记、梁阿婆、水街为街道近似；冰神用中山路美食街公开节点作为附近位置，**四家小店均未确认精确店址**。来源与核对结果见 [004 执行记录](../../../docs/tasks/004-parse-geocode.md)。交通方式沿用用户语料，用于视频演示。

**Nominatim 公益服务使用限制**：遵守 [官方使用规则](https://operations.osmfoundation.org/policies/nominatim/)，只在用户发起制作时小量查询，单机串行、最多每秒 1 次；不可用来高频、定期批量查询或自动补全。代码带专用 User-Agent、中文语言头，网络错误最多重试一次，结果缓存在 `.cache/geocode.json`（忽略 Git），第二次相同查询不联网。CLI 用锁文件防止同时查询；异常终止留下锁时，确认无查询进程后再移走 `.cache/geocode.json.lock`。团队应共享单一查询入口与缓存，不要分散多机器查询；量大时用自建服务。服务地址可用 `NOMINATIM_SEARCH_URL` 切换，例如自建的 `/search` URL，无需改代码或安装新依赖。

## 配置和时间

字段以 `src/config/schema.ts` 为准。必填项只有 `stops`（至少两站）；所有字段由 zod 校验，颜色为六位十六进制。`straight` 是地图直线；`greatCircle` 是大圆航线。不沿实际道路导航，也不限制路线距离。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `aspect` | `9:16` | 支持 `16:9`、`1:1` |
| `fps` | 30 | 每秒帧数 |
| `secondsPerLeg` | 3 | 每段画线时间 |
| `holdSeconds` | 1 | 到达后停留时间，可为 0 |
| `introSeconds` | 1.5 | 开场从全景推近第一站 |
| `outroSeconds` | 1.5 | 结尾拉远至全景 |
| `closeZoom` | 16.5 | 街道近景级别，允许 12–18；长路线实际级别自动降低 |
| `stops[].address` | 无 | 可选地址，无地址时只显示地名 |
| `stops[].mode` | `walk` | 从该点去下一点的方式：`walk` / `car` / `metro` / `train`；末站忽略 |
| `colors` | 橙色 | 路线默认 `#ff5a1f`，圆点默认 `#ed7b20`；`future` 可覆盖虚线颜色，默认由路线色提亮 30% |
| `attribution` | `end` | 片尾最后最多 2 秒淡入署名；`always` 全程显示 |

每段行进为 `max(1, round(secondsPerLeg × fps))` 帧，停留为 `round(holdSeconds × fps)` 帧。开场推近、结尾各为 `max(2, round(对应秒数 × fps))` 帧。第一站推近完成后也停留一次，供卡片阅读：总帧数 = 开场推近 + 第一站停留 + 段数 ×（行进 + 停留）+ 结尾。默认五站 20 秒，两站 8 秒。零停留不弹卡片，仍保留开场和结尾；倒着拖时间轴也能恢复正确画面。

成都示例的地址使用道路级展示文字，交通方式用于演示徽章切换，不是实际交通导航或线路建议。

## 固定底图怎样工作

底图分为两层。全景层保留 002 的单张板：9:16 使用 2160×3840，16:9 使用 3840×2160，1:1 使用 2160×2160，加载期间拟合整条路线。近景层在 `closeZoom` 下把路线范围加边距切成多块：每块内容最大 3072×3072，四周各多拍 64 px 后裁切，实际画布最大 3200×3200。所有画布像素比为 1。

样式标签优先 `name:zh → name:nonlatin → name`。加载阶段逐块移动相机，等 `idle` 后保存 PNG；全部块就绪才允许视频捕获。近景最多 16 块，超出就每次降低 0.25 级，并提示“路线较长，近景已自动调整为 X 级”。实际近景可以低于配置的 12 级下限。加载等待上限为 5 分钟。

路线、景点和两层底图使用同一套近景像素坐标；全景按 zoom 差换算。后续帧只移动图片和 SVG，不再移动 MapLibre 相机；推近时近景淡入、拉远时淡出，底图不会被强行放大。

镜头沿同一条投影路线跟随线头，徽章固定在画面中央偏下（高度 62%）；各段采用五次缓动，起止速度和加速度为零，行进不反复缩放。标签在近景板加载时一次性布局，默认贴近圆点，只有文字互相重叠时才按四侧换边，因此不会随镜头或移动徽章闪躲。画面只显示已走过的点和当前下一站；下一站出发时约 0.3 秒淡入放大并带脉冲光圈。路线有白色 casing 和 14 px 彩色线，已走点半径 16 px，下一站半径 22 px。到点时同一个地名用约 0.5 秒移动放大成白色卡片标题，背景展开后地址上浮；出发反向收回。长地名的小标签加省略号，卡片标题完整缩小或换行。零停留或不足两帧的停留只显示标签。emoji 使用系统彩色字体。右下角署名默认只在片尾显示，详见下面的 007 说明。

跨洲路线使用相同底图方案，近景只能到国家/地区级别。大圆跨越 180° 时展开经度、保留 SVG 子路径，并开启世界副本，防止路线横穿底图。底图来自网络，网络失败会明确阻止渲染。

## 007：短路段与片尾署名

短路段按倾斜后画面长度计算独立缩放，目标至少为画面宽的 35%，最高 18.5 级。行进中保持比例；停留时平滑准备下一段，无停留时只在出发约半秒内过渡。超过近景级别的段叠加局部高清底图，近景与局部合计最多 24 块；预算不足时降低级别、限制镜头放大并打印中文提示，避免使用模糊底图。顶端已去掉渐隐雾，覆盖范围仍按逆投影四角计算。

到站时同一份 emoji 从气泡中心移动到卡片标题左侧，气泡外壳缩小淡出；出发时返回。卡片为图标预留宽度，长标题完整换行。

默认 `attribution: "end"` 在片尾最后最多 2 秒淡入 `© OpenStreetMap contributors · OpenFreeMap · OpenMapTiles` 和 `openstreetmap.org/copyright`；片尾不足 2 秒则使用整个片尾，示例设为 2.5 秒。`"always"` 全程显示。数据许可要求注明来源，因此不提供完全关闭选项。按 [OpenStreetMap 官方署名指南](https://osmfoundation.org/wiki/Attribution_Guidelines#TV,_film,_or_video_productions)，地图为主要画面的作品应在地图角落署名，移动或缩放时不要求一直显示；本模板在最后的地图画面右下角保留署名和版权网址。发布时应保留这段片尾。

## 检查

新环境先执行 `npm run doctor`：逐项检查 Node/npm、依赖和worker、三个网络服务、Remotion Chrome及一次真实1秒渲染。每项失败后仍继续检查，最后打印中文表、原因与补救建议，失败退出码为1。模板原生TypeScript要求Node≥22.18；Node20虽满足基础版本门槛，仍需升级。依赖缺失先 `npm ci`，worker缺失执行 `npm run postinstall`；浏览器缺失执行 `npx remotion browser ensure`。视频在 `out/doctor.mp4`，渲染日志在 `out/doctor-render.log`。本机通过不表示其他工作空间也通过。

008到达构图：人或车在地点上停留，不进入气泡；卡片底边与徽章顶边相距26基准像素，卡片中心约在画面高度46%。到达和出发时用与卡片相同的缓动平滑调整固定底图偏移，行进仍沿路线向前。密集气泡先缩小已走点，再有限向上错开（偏移最长64基准像素），仍挤时允许部分重叠；下一站位于普通气泡上层。
